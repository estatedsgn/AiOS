# Первый APK-срез AIS

Это небольшой проверяемый сценарий, а не законченная ОС или CRM. Контракт: PR #3,
исходная точка `5752c86`. Реализация: PR #4, `ais/workspace-apk-slice`.
Во время разработки PR #3 получил параллельную реализацию. Этот срез использует
отдельный namespace `ai.aios.app.workspace` и не перезаписывает его ветку.
Перед объединением обоих PR требуется review интеграции двух точек входа.

## Что проверить первым

1. Открыть AIS обычной иконкой, не задавая API-ключ и не включая Accessibility.
2. Нажать «Выполнить» с командой `Задача: Связаться с Анной`.
3. Убедиться, что появилась локальная карточка. «Готово» / «Вернуть» меняет её статус.
4. Нажать «В календарь»: сначала появляется карточка с заголовком, риском EXTERNAL,
   маршрутом ANDROID и объяснением действия. До подтверждения ничего не открывается.
5. «Отклонить» и «Стоп» отменяют ожидающие действия. «Открыть календарь» однократно
   передаёт заголовок стандартному Android-редактору. Дата, время и сохранение — в календаре.
6. Вернуться в AIS → «Журнал»: ожидается HANDED_OFF, **не** «встреча создана».
   При отсутствии календаря ожидается BLOCKED, без фиктивного успеха или UI-обхода.
7. Принудительно остановить APK и открыть снова: задачи/статусы/история сохраняются.
   Старые ожидающие предложения отменяются; прерванные RUNNING становятся UNKNOWN.
   Ничего не воспроизводится автоматически.
8. «Приложения» и «Настройки» работают независимо от API, сети и чтения workspace.

Офлайн-команды: `Задача: …`, `Создай задачу: …`, `Сводка`, `Открой настройки`,
`Покажи экран`; также `Task: …`, `Create task: …`, `Brief`, `Open settings`,
`Inspect screen`. Это явные шаблоны, не универсальный языковой планировщик.
`Покажи экран` читает только пакет/число дочерних узлов текущего окна и требует
вручную включённого Accessibility. Текст экрана не сохраняется.

## Установка APK на stock Android

Целевой физический аппарат — Pixel 9 Pro. minSdk проекта — 26; CI smoke использует
обычный эмулятор API 35 / профиль Pixel 7 Pro и не заменяет тест на Pixel 9 Pro.

Для APK **не нужны OEM unlocking, fastboot, root, сброс данных или прошивка**.
Через USB нужны platform-tools, USB debugging и подтверждение компьютера на телефоне:

```sh
adb devices
adb install -r path/to/aios-COMMIT.apk
adb shell am start -n ai.aios.app/.workspace.WorkspaceActivity
```

Старые `tools/install.*` предназначены для прежнего эксперимента и могут включать
Accessibility / открывать MainActivity. Для этого smoke-сценария используйте команды выше.

Если Android сообщает `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, остановитесь: debug-подписи
разных CI-сборок могут различаться. Не удаляйте приложение автоматически — удаление
стирает весь его локальный workspace и настройки. Для теста используйте чистый эмулятор
либо согласованную стабильную debug-подпись. Локальные повторные сборки одним ключом
поддерживают обновление через `adb install -r`.

Домашний экран выбирается только пользователем: «Приложения» → «Выбрать домашний экран».
Возврат: системные настройки → приложения по умолчанию → главный экран → штатный launcher.
Есть кнопка «Вернуть системный launcher». Удаление обычным способом также удаляет локальные
данные AIS; отдельного ROM rollback для APK нет, разделы устройства не менялись.

## Реальные границы реализации

| Область | В этом срезе | Не заявляется готовым |
|---|---|---|
| Workspace | WorkItem, Proposal, Activity; задачи, очередь, локальная сводка | Полноценная CRM |
| Модели | Contact, Conversation, Deal также сохраняются и проходят round-trip | Их редакторы и CRM sync |
| Router | Schema/risk/verification + приоритет Android → service → Accessibility | Рабочий удалённый CRM adapter |
| Android | Settings intent и calendar insert intent | Подтверждённое сохранение встречи |
| Accessibility | Явное read-only чтение метаданных окна | Автоклики/отправки через новый router |
| Policy | READ/LOCAL; одноразовый EXTERNAL approval; SENSITIVE заблокирован | Безнадзорные sensitive-действия |
| AI | Детерминированные офлайн-команды | Универсальный LLM planner в этом workspace |
| System | Обычный APK, добровольный HOME role, ручной режим | ROM, privileged APIs, OTA |

Прежний LLM/Accessibility-эксперимент доступен отдельной кнопкой с предупреждением:
он имеет **свою** старую policy и не интегрирован с новым router. При возвращении
на workspace Home активный прежний run получает Stop.

## Проверки и хранение

```sh
./gradlew :core:test :app:assembleDebug --no-daemon
# Только на одноразовом эмуляторе: очищает данные AIS в этом эмуляторе.
python3 tools/smoke_workspace.py app/build/outputs/apk/debug/app-debug.apk --reset-test-data
```

`WorkspaceScenarios` содержит 27 проверок, запускаемых и напрямую Kotlin, и одной
JUnit-обёрткой в `:core:test`. Они проверяют TTL, повторный approval, отмену/поздний
результат, потерю маршрута без fallback, restart, сбой диска, codec и все 6 сущностей.
Не путать количество сценариев с количеством JUnit test cases.

Состояние: `files/workspace-v1.bin`, формат AIS1/v1, Android AtomicFile, один writer
на процесс, дисковые операции вне UI-потока. Лимиты preview: 100 задач, 100 предложений,
200 событий, максимум 2 MiB. Смена версии требует миграции; повреждение не сбрасывает
файл молча. Новые записи не содержат полей для токенов/паролей, тела уведомлений и
сырых текстов ошибок провайдера. Не вводите секреты в названия задач. Дополнительного
шифрования workspace сверх защиты Android sandbox здесь нет; APK предназначен для
тестовых данных. Облачная синхронизация и экспорт пользовательских данных не выполняются.

RUNNING сохраняется до внешнего вызова. Сбой после передачи может дать UNKNOWN:
это не доказательство отмены и не повод повторять действие. Stop отменяет текущую
корутину и очередь; уже переданный intent/внешний эффект отозвать невозможно.
Подтверждение привязано к неизменным аргументам/маршруту и истекает через 5 минут.

`workspace-smoke` публикует XML/скриншот эмулятора как `workspace-smoke-evidence`.
Обычный workflow `build` публикует APK как `aios-apk`. Статус CI нужно читать для
конкретного SHA. Успешная сборка, запуск эмулятора и физический Pixel smoke — три
разных уровня проверки; один не следует выдавать за другой.
